  1.  class DistanceEmissionCostStrategy[O, V] extends EmissionCostStrategy[O, V]

    Computes emission costs for candidates based on distance.

    This is an experimental API. It may be removed or changed from one version to the next.

    Computes emission costs for candidates based on distance.

    This strategy uses a simplified form of the negative log-probability derived from GaussianProbabilityDistribution. For an observation distance d, the Gaussian log-density is:

    log p(d) = c - 0.5 * (d / sigma)^2

    where c is a constant that depends only on sigma. Since the same constant is added to every candidate for the same observation, it does not affect which path has the best total score and is therefore omitted here. The remaining term is converted into a cost to be minimized:

    cost(d) = 0.5 * (d / sigma)^2

    This lets routing use Dijkstra-style minimization on additive costs instead of maximizing log-probabilities.

  9.  case class MatchedPath[V](results: IndexedSeq[MatchCandidate[V]], transitions: Seq[Transition[V]]) extends Product with Serializable

    The result of applying a StreamingPathMatcher to observations.

    This is an experimental API. It may be removed or changed from one version to the next.

    The result of applying a StreamingPathMatcher to observations.

    See also TransitionCostStrategy, which may compute transition data.

    V

    The type of the elements for Matched results

    results

    The MatchCandidate for each observation. The results will always have the same length as the input trace, and each element will correspond one to one with an input point in the same order. The type of result will indicate if the point was matched or not.

    transitions

    The Transitions between results if they were computed during matching. When computed the transitions will contain the information to reconstruct a path connecting results together.

    • Transitions are only emitted between two consecutive Matched results. An unmatched result suppresses both adjacent transitions: there will be no transition ending at the unmatched index and no transition starting from it.
    • For any transition t, t.from must be less than t.to.
    • For two consecutive transitions t1 and t2, t1.to must be less than or equal to t2.from (the transitions must be sorted in ascending order)

  19.  class ShortestPathRoutingStrategy[O, V, E, LS] extends PatchedRoutingStrategy[O, V]

    Shortest-path (distance-based) implementation of PatchedRoutingStrategy.

    This is an experimental API. It may be removed or changed from one version to the next.

    Shortest-path (distance-based) implementation of PatchedRoutingStrategy.

    Routes minimise a length-derived cost model and uses an A* heuristic derived from straight-line distance.

    The cost model is a simplified form of the negative log-probability of an ExponentialProbabilityDistribution. For distance d, the exponential log-density is:

    log p(d) = c - d / beta, where c = log(1 / beta).

    The constant c adds the same value to all competing transitions at the same step, so removing it does not change which path is best. To run Dijkstra as a minimization, we use the equivalent non-negative cost form:

    cost(d) = d / beta = d * lambda, where lambda = 1 / beta.

    In this strategy lambda is provided via Parameters.exponentialProbabilityDistributionLambda, and all components are kept in the same cost space:

    • vertex cost: patchedLength(v) * lambda
    • edge penalty: edgePenaltyMeters * lambda
    • heuristic: straight-line distance scaled by lambda
    • observer potential limit: distance limit scaled by lambda

    Keeping these terms in the same scaled space preserves consistent comparisons in Dijkstra/A* and avoids bias between route cost, heuristic guidance, and termination.

  22.  trait StreamingPathMatcher[O, V, S <: MatcherState] extends AnyRef

    Stateless streaming path matcher.

    This is an experimental API. It may be removed or changed from one version to the next.

    Stateless streaming path matcher.

    The matcher is stateless and reusable — state is held in an explicit MatcherState value that is passed in and returned by append. This separation allows the state to be serialized and transferred independently of the matcher (which may hold non-serializable strategy references), enabling distributed processing patterns.

    Usage:

    val matcher: StreamingPathMatcher[O, V, HMMMatcherState[O, V]] = ...

val s1 = matcher.append(HMMMatcherState.empty, Seq(o1, o2, o3))
val s2 = matcher.append(s1, Seq(o4, o5))
val result: MatchedPath[V] = matcher.matchedPath(s2)
